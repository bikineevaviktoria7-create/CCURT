# Тренажёр русского жестового языка

Фронтенд на Vite, React 18, TypeScript и Tailwind. Сервер, база данных, отправка email и настоящее распознавание жестов не реализуются в этом проекте: для них предусмотрены границы сервисов и адаптера.

## Запуск

Node.js 22.12+. Все команды выполняются из `CCURT`:

```sh
npm ci
npm run dev
```

Открыть <http://127.0.0.1:5173>.

```sh
npm run build
npm run preview
npm run lint
npm test
```

Production preview: <http://127.0.0.1:4173>.

## Основной сценарий

Начальная → вход / регистрация / гость → главная с единой дорожкой → страница занятия → **теория всех жестов** → «Теперь попробуйте сами» → **практика всех жестов** → результат → главная / следующее занятие.

Например, в первом уроке: А → Б → В (теория), затем А → Б → В (практика). Успех автоматически переводит к следующему жесту через 950 мс. Между жестами практики нет возврата к теории.

Отдельных обязательных onboarding- и calibration-страниц нет. Запрос камеры появляется только после «Начать практику». Главная — дорожка из 20 уроков: 10 по алфавиту и 10 по словам. После завершения урок закрашивается, следующий открывается. Повторение алфавита начинается с шестого урока.

## Маршруты

| Адрес                     | Экран                          |
| ------------------------- | ------------------------------ |
| `/`                       | Короткая начальная страница    |
| `/login`                  | Вход                           |
| `/register`               | Регистрация                    |
| `/verify-email`           | Подтверждение email            |
| `/dashboard`              | Главная с дорожкой обучения    |
| `/lessons/:lessonId`      | Содержание занятия             |
| `/lessons/:lessonId/play` | Вся теория, затем вся практика |
| `/results/:sessionId`     | Сохранённый результат          |
| Неизвестный адрес         | 404 с возвратом                |

Учебные страницы защищены гостевой/аккаунтной сессией. Нельзя открыть заблокированный урок прямой ссылкой. При обновлении незавершённого занятия оно начинается с теории; завершённые результаты и прогресс сохраняются.

## Что сейчас является демонстрацией

- **Авторизация:** `authService` хранит demo-аккаунты локально в браузере. Это не серверная авторизация. Пароли сохраняются только в виде хэша с солью; для демо используйте тестовые данные. После регистрации код — **123456**, он указан на экране. Email не отправляется. Для входа сначала создайте и подтвердите локальный аккаунт.
- **Распознавание:** камера показывает реальное локальное видео, но `MockVisionAdapter` не анализирует движения. Кнопка «Запустить демонстрацию» проигрывает сценарий ожидание → распознавание → конкретная подсказка → удержание → успех. На следующих жестах демонстрация продолжается автоматически. Демо доступно и при отказе/отсутствии камеры.
- **Skeleton:** canvas показывает иллюстративную схему, которая не привязана к реальной руке и не является эталоном РЖЯ. Ошибочные области выделены coral, успешные — зелёным.
- **Эталоны:** проверенные фото/GIF/видео и описания РЖЯ ещё не предоставлены. Вместо выдуманных жестов показаны заглушки. Тип движения у слов — предварительная метаинформация.
- **Результаты:** детерминированная оценка демонстрации: 100 за жест, −8 за отмеченную коррекцию, 0 за пропуск, затем среднее в процентах и перевод в 0–1000 очков. Это не оценка реального владения РЖЯ.

Панель ручного переключения состояний и ползунки доступны только при `import.meta.env.DEV`. В production остаётся явно обозначенная демонстрация для проверки frontend-flow, без панели разработчика.

## Точки интеграции для backend/CV-разработчика

| Файл                                | Назначение                                                                             |
| ----------------------------------- | -------------------------------------------------------------------------------------- |
| `src/services/authService.ts`       | Заменить локальный mock на вызовы авторизации, регистрации и подтверждения email       |
| `src/services/lessonService.ts`     | Репозиторий контента, возвращающий `Lesson`, а не сырые строки БД                      |
| `src/services/progressService.ts`   | Чтение/сохранение результатов, доменная модель прогресса и подсчёт баллов              |
| `src/types/`                        | Типы `User`, `Lesson`, `Gesture`, `LessonResult`, `RecognitionResult`, `VisionAdapter` |
| `src/integrations/visionAdapter.ts` | Изолированная демонстрация; место подключения реального адаптера                       |
| `src/hooks/useRecognition.ts`       | Подписка на семантические результаты и отдельный канал canvas-кадров                   |
| `src/lib/drawHandSkeleton.ts`       | Рендер 21 landmark с mirroring и object-fit: contain                                   |

CV-пайплайн должен жить за `VisionAdapter`. Координаты кадров не записываются в React state. Итоговые состояния mock-адаптера приходят не чаще 10 Гц, canvas рисуется напрямую. `useCamera` останавливает tracks при выходе и корректно закрывает stream, если разрешение пришло после ухода со страницы. Никакие кадры на сервер не отправляются.

Последовательность урока централизована в `lessonSessionReducer`, а не в визуальных компонентах. `AppProvider` хранит только пользователя и прогресс. Данные гостя и локальных аккаунтов разделены по ID. Работа с localStorage сосредоточена в `storage.ts`; при недоступности хранилища интерфейс предупреждает о временном сохранении в памяти.

Название продукта находится в одной константе `APP_NAME` в `src/app/constants.ts`. Общие цвета, радиусы и длительности — в `src/styles.css`. Шрифт Manrope поставляется локально.

## Проверка

`npm test` проверяет обязательную последовательность всей теории перед практикой, защиту от повторного принятия результата, подсчёт баллов и открытие следующего урока.

Ручная проверка:

1. Выбрать гостя на начальной странице: сразу откроется дорожка.
2. Открыть первый урок, нажать «Начать»; просмотреть А, Б, В кнопкой «Далее».
3. Только после всех трёх нажать «Начать практику»; разрешить камеру или использовать демонстрацию без неё.
4. Запустить демонстрацию, увидеть подсказку и подсветку, затем последовательный успех А, Б, В.
5. На результате проверить точность, очки, ошибки; перейти к следующему уроку или на главную.
6. Обновить страницу: первый урок завершён, второй текущий.
7. Отдельно проверить регистрацию/код/вход, пропуск, выход из урока, отказ камеры, 404 и ширины 1440/1024/390 px.

## Развёртывание

Проверка текущей версии: `build`, `lint` и три теста проходят. В изолированном Chrome с тестовым видеопотоком проверены dev- и production-сценарии, регистрация/вход, сохранение после refresh, запрет раннего запуска камеры, автоматические переходы практики, ошибки камеры и пропуск. Основные экраны просмотрены на 1440/1024/390 px; горизонтального переполнения и ошибок JavaScript не обнаружено. Автоматическая проверка axe для проверенных экранов production не выявила нарушений WCAG A/AA. Реальные устройства, Safari/Edge и подключение backend/CV остаются отдельной интеграционной проверкой.

Vercel: `npm run build`, выходной каталог `dist`. Если импортируется родительский репозиторий, Root Directory — `CCURT`. `vercel.json` обеспечивает SPA fallback для прямого открытия вложенных маршрутов. Для камеры в production нужен HTTPS; localhost подходит для разработки.
