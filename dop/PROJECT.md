# SignStep — тренажёр русского жестового языка

Веб-приложение, в котором веб-камера становится учителем: пользователь показывает буквы дактильной азбуки и слова русского жестового языка (РЖЯ). Приложение распознаёт жест прямо в браузере, сверяет его с эталонами из базы данных, а если жест неточный, говорит, **что именно исправить** («Согните мизинец — сейчас он выпрямлен»).

**ADMIT Hackathon 2026 · кейс «Motion» · направление C (свободный вариант).**

- Деплой: `https://<ваш-проект>.vercel.app` ← вписать после деплоя
- Демо-вход: **Руслана, Камилла, Мария**. Пользователи и общий пароль заданы в `DEMO_USERS` / `DEMO_PASSWORD` в `src/app/constants.ts`.
- Гость: **Предпросмотр** — один тест обнаружения и удержания руки, затем предложение войти. Этот тест не оценивает РЖЯ.
- Иллюстрации алфавита и образцы распознавания находятся в `public/`. Описание форматов: [материалы жестов](GESTURE_MEDIA.md).

## Для кого

Для глухих и слабослышащих людей и их окружения: родственников, друзей, коллег, волонтёров. Основная обратная связь визуальная (цвет, подсветка пальцев, текст). Звук, озвучка и вибрация — дополнительные и отключаются в настройках.

## Сценарий

Начальная → временный вход → главная с дорожкой из 20 доступных уроков → страница занятия → теория всех жестов → «Начать практику» → практика всех жестов → итоги → главная / следующий урок.

Гостевой сценарий отделён: начальная → «Предпросмотр» → инструкция → камера и обратная связь → результат одного теста → вход. Гостевые маршруты и сервисы не дают доступ к обычным урокам и прогрессу.

- **Раздел 1 «Алфавит»** — 10 уроков: 1–5 изучение по 3 буквы, 6–10 повторение.
- **Раздел 2 «Основные слова»** — 10 уроков: привет/пока, да/нет, спасибо…, урок 5 — **«Знакомство: своё имя»**: после слов пользователь показывает своё имя дактилем, буква за буквой.

## Что распознаётся

| Что | Как |
| --- | --- |
| Статичные буквы дактиля (А, Б, В, Г, Е, И, Л, М, Н, О, П, С, Т, У, Ш и остальные для имени) | форма руки: kNN по вектору признаков |
| Буквы с движением (Д, З, Й, Ё, Ц, Щ, Ъ) и слова | траектория: сегментация движения + DTW |

Каждый жест вызывает своё действие: засчитывается в уроке и открывает следующий шаг, ошибка даёт конкретную подсказку.

## Как реализован режим «ошибка» (твист)

В уроке целевой жест известен, поэтому попытка сравнивается **с ближайшим эталоном именно этого жеста** по группам признаков (`src/vision/errorAnalyzer.ts`):

1. Для каждой группы — каждый палец, большой палец, разведение пальцев, поворот ладони — считается отклонение от эталона.
2. Порог ошибки берётся **из разброса эталонов команды**: 10+ записей одного жеста показывают естественную вариативность, и всё, что сверх неё, считается ошибкой.
3. Самое уверенное отклонение превращается в конкретную инструкцию и подсветку точек руки. Ошибочный палец становится красным, верные пальцы — зелёными.
4. Если рука ближе к **другому** жесту из базы, приложение говорит об этом: «Сейчас это похоже на «Б». Согните указательный палец…».
5. Подсказка не «прыгает»: показывается самая частая ошибка за последние кадры, текст меняется не чаще раза в 1,2 с.
6. Коды ошибок сохраняются в попытках, на экране итогов видно «Частые ошибки».

Примеры подсказок:

- «Согните безымянный палец — сейчас он выпрямлен.»
- «Соедините большой и указательный пальцы — кончики должны касаться.»
- «Разведите указательный и средний пальцы шире.»
- «Поверните ладонь к камере — сейчас она повёрнута ребром.»
- «Направьте пальцы вверх.»
- Для слов: «Сделайте движение шире.», «Переместите руку выше.», «Сделайте движение медленнее.»
- Окружение: «Рука не полностью в кадре — отодвиньте её немного дальше.», «Слишком темно — включите свет».

## Алгоритм (собственная логика команды)

MediaPipe используется только для того, чтобы найти 21 точку руки (и плечи/нос для слов). Всё остальное написано командой в `src/vision/`. Это чистые функции без DOM, они покрыты тестами.

1. **Нормализация** (`normalize.ts`): запястье в начало координат, масштаб по длине ладони. Левая рука зеркалится, поэтому одни эталоны подходят обеим рукам. Метки handedness от MediaPipe исправляются: модель считает кадр зеркальным, а мы передаём исходный.
2. **Признаки** (`features.ts`, 34 числа по `worldLandmarks` — 3D-координатам в метрах):
   - углы сгибания каждого сустава;
   - положение большого пальца;
   - разведение пальцев и касания кончиков;
   - нормаль и направление ладони.
   Ориентация не выравнивается специально: в дактиле она различает буквы.
3. **Буквы** (`staticMatcher.ts`): взвешенное расстояние до эталонов. Порог принятия каждого жеста вычисляется по его собственным эталонам. Жест не засчитывается, если другой жест из базы явно ближе.
4. **Стабилизация** (`stabilizer.ts`): жест засчитан, если он лидирует в 8 из 12 последних кадров и удерживается 0,6 с. Удержание показывает кольцо прогресса.
5. **Слова** (`dynamicMatcher.ts`): движение вырезается из потока — начало по скорости руки, конец по остановке. Затем оно приводится к 24 кадрам и сравнивается с эталонами через DTW с окном Сако–Чиба. Ошибки: положение руки относительно лица, амплитуда, скорость, форма пальцев.
6. **Решение** (`recognizer.ts`): кадр на входе → статус (`success / almost / incorrect / environment-error`) и подсказка на выходе.

Производительность: модель загружается один раз, кадры обрабатываются через `requestVideoFrameCallback`. Точки руки идут сразу на canvas, минуя React state, а результаты передаются в интерфейс не чаще 10 раз в секунду. GPU с автоматическим переходом на CPU.

## Приватность

Видео с камеры **не покидает устройство**. В базе хранятся только числовые координаты эталонов (их записывает команда) и результаты уроков.

## Архитектура

```
src/
  vision/          собственная логика распознавания (чистые функции) + landmarkers.ts (MediaPipe)
  integrations/    createMediaPipeVision (камера → распознаватель), createMockVision (демонстрация)
  hooks/           жизненный цикл камеры, распознавания и занятия; загрузка уроков
  services/        authService (Supabase / локально), gestureRepository (эталоны и фото),
                   progressService (local-first), syncService (фоновая синхронизация),
                   gestureLibrary (загрузка эталонов и подготовка моделей), settingsService
  pages/           экраны обучения и предпросмотра
  data/            структура уроков и алфавит (работают без сети)
supabase/
  migrations/      001 схема · 002 профили/роли · 003 RLS · 004 хранилище фото · 005 таблица рекордов
  seed.sql         словарь жестов
public/
  data/samples.json  резервная копия эталонов (если база недоступна)
  models/            модели MediaPipe (npm run models)
```

[Карта кода для защиты](CODE_DEFENSE.md): порядок открытия 10 основных файлов, объяснение алгоритма и границ рефакторинга.

### Сохранённая интеграция Supabase (не используется для текущего входа)

| Таблица | Содержимое | Доступ (RLS) |
| --- | --- | --- |
| `profiles` | имя, роль `user/admin` | своя строка; роль меняет только админ |
| `gestures` | словарь жестов: описание, фото, свои подсказки | читают все, пишет админ |
| `gesture_samples` | эталоны: вектор признаков / последовательность, сырые точки | читают все, пишет админ |
| `lesson_results` | результаты уроков (id = sessionId, без дублей) | только свои |
| `get_leaderboard()` | сумма лучших результатов, только имя | все |

В текущем mock-режиме прогресс вошедшего пользователя хранится локально, отправка результатов в Supabase отключена. Предпросмотр не создаёт прогресс уроков. Существующая реализация фоновой синхронизации сохранена для будущего подключения серверной авторизации.

## Запуск локально

Node.js 22.12+.

```sh
cd CCURT
npm ci             # также копирует WASM MediaPipe в public/mediapipe
npm run models     # один раз: скачивает модели в public/models (закоммитить их)
# Supabase для текущего временного входа не требуется.
npm run dev        # http://127.0.0.1:5173
```

Проверки: `npm run build`, `npm run lint`, `npm test` (сценарий урока, доступ, прогресс, признаки, анализ ошибок, стабилизация, жизненный цикл адаптера и canvas).

`MOCK_AUTH_ENABLED` включает временную авторизацию. Полноценная серверная авторизация и защита серверных данных остаются задачей backend.

1. Создать проект на supabase.com. **SQL Editor** → выполнить по очереди `supabase/migrations/001…005` и `supabase/seed.sql`.

## Деплой (Vercel)

Root Directory — `CCURT`, сборка `npm run build`, каталог `dist`. При подключении Supabase задать `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. `vercel.json` отдаёт SPA-маршруты, не трогая `/models`, `/mediapipe`, `/data`. Камере нужен HTTPS. Если моделей нет в `public/models`, они загружаются с CDN Google.
