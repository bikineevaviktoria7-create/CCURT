# Правила унификации кода (обязательны для каждого шага)

Этот файл читает каждый агент перед началом работы. Нарушение любого пункта = шаг считается проваленным.

## 1. Что можно
- Единые названия файлов, функций, типов, переменных — по `dop/STYLE.md`.
- Убрать дублирование: одинаковый код → один модуль/хелпер, копии удалить.
- Единый порядок импортов, единый стиль экспорта, короткие комментарии к публичным функциям.
- Обновить все места использования переименованного — в том же шаге.
- Обновить `README.md` и `dop/CODE_DEFENSE.md`, если в них упоминаются переименованные файлы или функции.

## 2. Что нельзя (поведение приложения не меняется)
- Числа: пороги распознавания, веса, тайминги, очки, размеры — ни одно числовое значение не меняется.
- Тексты для пользователя (всё на русском в интерфейсе и подсказках) — не меняются.
- Ключи localStorage / IndexedDB, формат `public/data/samples.json`, запросы и таблицы Supabase — не меняются.
- Маршруты (URL страниц), порядок уроков, id жестов — не меняются.
- Внешний вид (CSS-классы, которые используются в `src/styles.css`, разметка) — не меняется.
- Нельзя трогать файлы вне папок, указанных в задаче. Исключение: обновить импорты в других файлах после переименования.
- Нельзя менять логику проверок в тестах, удалять или пропускать тесты (`skip`, `todo`), чтобы они «прошли».
- Нельзя добавлять `eslint-disable`, `@ts-ignore`, `@ts-expect-error`, `any`, ослаблять `tsconfig` или `eslint.config.js`.
- Нельзя устанавливать или удалять пакеты, менять `package.json` и `package-lock.json`.
- Нельзя удалять файл, пока поиск (`grep -rn`) не показал, что он нигде не используется. Удалённые файлы — в отчёт.
- Нельзя `git commit`, `git push`, `git reset`, `git checkout`, `git stash`, `git clean`. Разрешены `git status`, `git diff`, `git log` и одно исключение: `git restore <файл>` — только чтобы откатить СВОИ изменения этого шага при провале (раздел 3, п. 4).
- Этот этап — унификация: code-architect работает только в **безопасном режиме**. «Режим ООП» на этом этапе не включается, даже если его описание агента это допускает: классы не создаются, фабрики и функции не переводятся на классы. ООП — отдельный этап, по отдельной команде: на нём действует `dop/OOP_RULES.md`, и он имеет приоритет над этим пунктом.

## 3. Как работать
1. Прочитай `dop/STYLE.md`, `dop/CODE_DEFENSE.md` и `.qa/baseline.md` (если есть).
2. Составь короткий план (какие файлы, что меняешь). Если изменений больше 15 файлов — раздели на подшаги и после каждого подшага запускай проверку.
3. Меняй маленькими порциями. После каждой порции: `npm run typecheck`.
4. Если проверка упала — максимум 2 попытки исправить. Не получилось — откати свои изменения этого шага (`git diff --name-only` → верни каждый файл через `git restore <файл>`; новые файлы, которые ты создал на этом шаге, удали через `rm`) и напиши отчёт «СЛОМАНО».
5. Если понимаешь, что задача больше, чем ожидалось, или контекст заканчивается — остановись в состоянии, где проект собирается, и напиши отчёт «НЕ ЗАВЕРШЕНО» со списком того, что осталось.

## 4. Обязательная проверка в конце шага
Выполни всё по порядку и запиши результат каждой команды:
1. `npm run typecheck` — без ошибок.
2. `npm run lint` — 0 ошибок и 0 предупреждений.
3. `npm test` — число тестов не меньше, чем в `.qa/baseline.md`, `fail 0`.
4. `npm run build` — сборка прошла.
5. Запуск собранного сайта: `npx vite preview --port 4173 --strictPort &`, подождать 3 секунды, затем `curl -s -o /dev/null -w "%{http_code}"` для адресов:
   `/`, `/data/samples.json`, `/models/hand_landmarker.task`, `/assets/gestures/letter-1.svg` — все должны вернуть `200`. После проверки остановить сервер: `pkill -f "vite preview"`, затем убедиться, что порт свободен: `lsof -i :4173` ничего не выводит (если выводит — `kill <PID>` из вывода). Перед запуском тоже проверь, что порт 4173 свободен.
6. Проверка «поведение не изменилось»: выполни
   `git diff -U0 -- src | grep -E '^[-+]' | grep -vE '^(\+\+\+|---)' | grep -E '[0-9]+\.[0-9]+|[0-9]{2,}|[А-Яа-яЁё]|localStorage|storage\.|path:|"/'`
   Для каждой найденной строки объясни, почему это не изменение поведения (например, строка просто переехала в другой файл без изменений). Если объяснить нельзя — это нарушение, откати.
7. `git status --short` — перечисли все изменённые, новые и удалённые файлы.

## 5. Формат отчёта (строго)
```
ПРОВЕРКА: ВСЁ РАБОТАЕТ | СЛОМАНО | НЕ ЗАВЕРШЕНО
typecheck: ok/ошибка · lint: 0 предупреждений/N · test: X/Y · build: ok/ошибка · preview: 200 на всех адресах/какие нет
Поведение: не изменено (проверено diff) / найдено: …
Что сделано: 1–3 предложения
Файлы: изменено N, создано N, удалено N (список)
Документация: обновлена / не требовалась
Что проверить вручную: …
Риски и что осталось: …
```
Первая строка отчёта — только одно из трёх слов. Не пиши «ВСЁ РАБОТАЕТ», если хоть один пункт проверки не выполнен.
